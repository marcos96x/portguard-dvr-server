Documentação de uso

API para cadastrar DVRs de forma dinâmica no go2rtc e devolver, para cada câmera, as URLs prontas que o webapp (HTML, CSS e JS) usa para exibir o vídeo.

Introdução

O navegador não toca RTSP. Este serviço roda numa VM Linux na nuvem, puxa o RTSP de cada DVR (porta 554) e entrega WebRTC, MSE, HLS ou um JPEG para o aplicativo.

Um único servidor atende vários DVRs. Cada câmera vira um stream com o nome <id-do-dvr>_ch<N>. As senhas dos DVRs nunca voltam nas respostas: o campo password aparece como ********.

As rotas públicas desta API são GET /docs e GET /health. Todas as rotas em /api/* exigem o token de autenticação.

Autenticação

O token fica no arquivo .env, na variável API_KEY. Envie esse valor no header HTTP X-API-Key em todas as requisições para /api/*.

Sem o header, ou com um token diferente do que está no .env, a API responde 401 com a mensagem de chave inválida ou ausente.

Exemplo com curl

curl -sS http://127.0.0.1:3000/api/dvrs \
  -H "X-API-Key: SEU_TOKEN"

Troque SEU_TOKEN pelo valor de API_KEY definido no .env do servidor. Não compartilhe esse valor em repositórios nem no código do webapp que roda no navegador do cliente final — a API de gestão deve ser chamada pelo seu backend.

Exemplo com JavaScript (fetch)

const resposta = await fetch("http://127.0.0.1:3000/api/dvrs", {
  headers: {
    "X-API-Key": "SEU_TOKEN",
    "Content-Type": "application/json"
  }
});
const dados = await resposta.json();

Para POST e PUT, mantenha o mesmo header X-API-Key e envie o JSON no corpo da requisição.

Rotas

Base padrão da API: http://127.0.0.1:3000 (variável PORT no .env).

GET /health Pública

Saúde da API e alcance do go2rtc. Não exige token e não devolve senhas. Retorna 200 se o go2rtc estiver acessível e autenticado, ou 503 caso contrário. 

curl -sS http://127.0.0.1:3000/health
{
  "ok": true,
  "service": "portguard-dvr-server",
  "time": "2026-11-18T12:00:00.000Z",
  "go2rtc": { "reachable": true, "status": 200, "authorized": true }
}
GET /docs Pública

Esta página de documentação (HTML). Não exige token.

curl -sS http://127.0.0.1:3000/docs
GET /api/dvrs X-API-Key

Lista todos os DVRs cadastrados, com as URLs de cada câmera. Senhas mascaradas.

curl -sS http://127.0.0.1:3000/api/dvrs \
  -H "X-API-Key: SEU_TOKEN"
{ "dvrs": [ /* objetos no mesmo formato de GET /api/dvrs/:id */ ] }
GET /api/dvrs/:id X-API-Key

Devolve um DVR específico. Responde 404 se o id não existir.

curl -sS http://127.0.0.1:3000/api/dvrs/loja-centro-a1b2c3 \
  -H "X-API-Key: SEU_TOKEN"
POST /api/dvrs X-API-Key

Cadastra um DVR, cria os streams correspondentes no go2rtc e devolve as URLs prontas para o webapp. O id é gerado automaticamente a partir do nome.

O campo channels aceita a quantidade (4 gera as câmeras 1 a 4) ou uma lista ([1, 3, 5]). O padrão de URL é Intelbras: 

rtsp://usuario:senha@host:porta/cam/realmonitor?channel=N&subtype=S

subtype padrão: 1 (substream, mais leve para web/celular). Use 0 para o stream principal. Para outro fabricante, envie rtspTemplate com os placeholders {username}, {password}, {host}, {rtspPort}, {channel} e {subtype}.

CampoObrigatórioDescrição
namesimNome amigável do DVR (usado para gerar o id)
hostsimDDNS ou IP público do DVR
usernamesimUsuário do DVR (prefira um só de visualização)
passwordsimSenha do DVR (não volta na resposta)
channelssimQuantidade ou array de canais
rtspPortnãoPadrão: 554
subtypenãoPadrão: 1
brandnãoPadrão: intelbras
rtspTemplatenãoTemplate RTSP customizado
 
curl -sS -X POST http://127.0.0.1:3000/api/dvrs \
  -H "Content-Type: application/json" \
  -H "X-API-Key: SEU_TOKEN" \
  -d '{
    "name": "Loja Centro",
    "host": "loja-centro.ddns-intelbras.com.br",
    "rtspPort": 554,
    "username": "visualizador",
    "password": "senha-do-dvr",
    "channels": 2,
    "subtype": 1,
    "brand": "intelbras"
  }'

PUT /api/dvrs/:id X-API-Key

Atualiza um DVR já cadastrado e recria os streams no go2rtc. Envie só os campos que deseja alterar. Para manter a senha atual, omita password ou envie ********. 

curl -sS -X PUT http://127.0.0.1:3000/api/dvrs/loja-centro-a1b2c3 \
  -H "Content-Type: application/json" \
  -H "X-API-Key: SEU_TOKEN" \
  -d '{"channels":[1,2,3],"subtype":1}'
DELETE /api/dvrs/:id X-API-Key

Remove o DVR da persistência e apaga os streams correspondentes no go2rtc.

curl -sS -X DELETE http://127.0.0.1:3000/api/dvrs/loja-centro-a1b2c3 \
  -H "X-API-Key: SEU_TOKEN"
{
  "ok": true,
  "id": "loja-centro-a1b2c3",
  "go2rtc": { "synced": true, "created": 2, "failed": 0, "errors": [] }
}
POST /api/sync X-API-Key

Recria no go2rtc todos os streams salvos. Útil depois de reiniciar só o go2rtc, porque ele esquece os streams que estavam só na memória. A API também faz isso automaticamente na subida e a cada intervalo (SYNC_INTERVAL_MS, padrão 30 segundos). 

curl -sS -X POST http://127.0.0.1:3000/api/sync \
  -H "X-API-Key: SEU_TOKEN"
{
  "ok": true,
  "dvrCount": 1,
  "go2rtc": { "synced": true, "created": 2, "failed": 0, "errors": [], "mode": "ensure", "expected": 2 }
}
GET /api/clip X-API-Key

Devolve um vídeo MP4 (H.264) com os últimos seconds da câmera, lidos da gravação do DVR (RTSP Intelbras /cam/playback). O parâmetro src é o streamName ou streamNameMain. seconds é opcional (padrão 15, mínimo 5, máximo 30). 

curl -sS -H "X-API-Key: SEU_TOKEN" \
  -o clip.mp4 \
  "http://127.0.0.1:3000/api/clip?src=loja-centro-a1b2c3_ch1&seconds=15"

O intervalo usa o relógio do DVR (header HTTP Date da porta 8001, tratado como America/Sao_Paulo). Se uma janela falhar com 4xx, a API tenta recuos de 2s, 15s, 30s e 60s. Neste firmware o playback não aceita subtype e vem em H.265 1280×720; a API converte para H.264 para o navegador conseguir tocar. No máximo 2 clipes ao mesmo tempo.

Não chame esta rota direto do JavaScript público: ela exige a API_KEY. O webapp deve pedir o clipe ao backend do Portguard, que então chama esta API.

Incorporar no webapp

Depois de cadastrar o DVR com POST /api/dvrs, use o array cameras[].urls no seu HTML. O caminho mais simples é um iframe apontando para urls.iframe (página stream.html do go2rtc): 

<iframe
  src="http://SEU_SERVIDOR:1984/stream.html?src=loja-centro-a1b2c3_ch1"
  allow="autoplay; fullscreen"
  title="Câmera 1"
></iframe>

No JavaScript, depois da resposta da API:

const cam = dvr.cameras[0];
document.getElementById("player").src = cam.urls.iframe;

As demais URLs, conforme a necessidade do player:

CampoUso
urls.iframePlayer pronto em stream.html (mais simples)
urls.webrtc / urls.webrtcPlayerWebRTC (menor atraso)
urls.mseWebSocket MSE (player próprio, ex. video-rtc.js)
urls.hlsHLS (stream.m3u8)
urls.snapshotJPEG atual (frame.jpeg)
urls.mjpegFluxo Motion JPEG

Há um exemplo pronto em examples/player.html. Em produção, aponte PUBLIC_GO2RTC_URL no .env para o endereço HTTPS que o navegador do usuário alcança (e não para o 127.0.0.1 da VM).

Não coloque o API_KEY no JavaScript do webapp público. O cadastro de DVRs deve passar pelo seu backend. O navegador do cliente final só precisa das URLs de reprodução devolvidas em cameras[].urls.

Persistência e sync

Os streams criados pela API do go2rtc ficam só na memória e somem se ele reiniciar. Por isso esta API grava os DVRs em data/dvrs.json e recria tudo na subida e a cada SYNC_INTERVAL_MS. Você também pode chamar POST /api/sync manualmente.

Erros comuns

HTTPQuando acontece
401Header X-API-Key ausente ou diferente do API_KEY do .env
400Corpo inválido (campos faltando, id inválido, etc.)
404DVR, câmera (src) ou rota não encontrados
409GET /api/clip quando o DVR não devolveu gravação na janela pedida
429Já há 2 clipes sendo gerados
503GET /health quando o go2rtc está inacessível ou a senha não confere
504Timeout ao gerar o clipe (transcode / relógio do DVR)
500Erro interno (veja os logs do serviço)
